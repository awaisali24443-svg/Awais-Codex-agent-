# Deploying to Render

The short version, for a free Render service plus a free Neon database. Ten minutes, no local
build, no Docker, no CLI. Everything below is dashboard clicks and pastes.

## What you need before you start

| Value | Where it comes from |
|---|---|
| `DATABASE_URL` | [neon.tech](https://neon.tech) → New Project → **Connection string** → pick **Pooled connection** (the host contains `-pooler`) |
| `MASTER_KEY` | `openssl rand -hex 32` — 64 hex characters, generated once, never changed afterwards |
| `GEMINI_API_KEY` | [aistudio.google.com/apikey](https://aistudio.google.com/apikey) |
| `WHATSAPP_TOKEN` | Optional. WhatsApp → **Settings → Agents →** your agent's chat → **Chat info → API key** |

`SESSION_SECRET` and `ACCESS_KEY` are generated by Render — you never see them until you read them
back in step 5.

## 1. Get `render.yaml` onto the default branch

Render's Blueprint reads `render.yaml` from the branch you pick. The easiest path is to merge the
open pull request into `main`; if you would rather not merge yet, Render lets you choose the branch
in the next step instead.

## 2. Create the Blueprint

[render.com](https://dashboard.render.com) → **New +** → **Blueprint** → connect GitHub → pick this
repository → **Apply**.

Render reads `render.yaml` and asks you to fill in the four values marked `sync: false`:

* `DATABASE_URL` — the Neon **pooled** string, exactly as copied (keep `?sslmode=require`)
* `MASTER_KEY` — the 64 hex characters
* `GEMINI_API_KEY` — paste it; you can also leave this empty and store the key in the app instead
  (step 6), but setting it here means the first mission works immediately
* `WHATSAPP_TOKEN` — paste it, or leave empty and paste the agent key in the app's Settings panel

Then **Apply**. The first build takes 2–3 minutes.

## 3. Watch the first boot

Open the service → **Logs**. A healthy first boot ends with lines like:

```
[boot] migrations: 1 applied, 0 present
[boot] engine: antigravity
[boot] whatsapp: not connected — add the agent API key in Settings to connect
[boot] listening on http://0.0.0.0:10000
```

The service is only marked live once `/healthz` answers, which is why `healthCheckPath` is set in
`render.yaml`.

## 4. Open your link (once)

Dashboard → your service → **Environment** → copy `ACCESS_KEY`, then open:

```
https://<your-service>.onrender.com/?k=<ACCESS_KEY>
```

The `?k=` is stripped from the address bar and the browser keeps a signed session for a year. There
is also a sign-in screen that accepts the same key. Nothing works without it — `/api` is deny by
default.

Bookmark the URL **without** the key afterwards; the session cookie is what authenticates you from
then on.

## 5. Check it is really working

* `https://<your-service>.onrender.com/healthz` → `{"ok":true,...}`
* `https://<your-service>.onrender.com/readyz` → `database: ok`, `engine: key present (...)`, and
  `poller: running` if the WhatsApp key is in place
* In the app: drawer → **Settings** → the Gemini key shows a fingerprint, WhatsApp shows
  *connected* (or tells you why not)

## 6. Optional: stop putting keys in the dashboard

Once `MASTER_KEY` is set, the app can hold its own credentials:

drawer → **Settings** → **Google AI Studio key** → **Replace** → paste → Save.

It is encrypted with AES-256-GCM, never sent back to the browser, and used from the next mission —
no redeploy. Same for the WhatsApp agent key, and storing that one **starts the poller by itself**.

## Free tier, honestly

* **The service sleeps** after ~15 minutes idle. The next request takes 30–60 seconds to wake it.
  The WhatsApp poller stops while it sleeps; messages sent during that time are picked up on the
  next poll after it wakes, and any message that was mid-flight is finished by the boot reconcile.
* **Neon also suspends** an idle database. The first query after that pays a cold start; the
  database layer retries once instead of failing the request.
* **Budgets**: `DAILY_RUN_BUDGET=100` is enforced in the database, per channel. You can change it
  live in Settings.
* **Retention**: run events are pruned after 14 days, artifact files after 7 — both configurable.

### Scheduled tasks on the free tier

The in-process scheduler ticks every 60 seconds, but **it cannot fire while the service sleeps**.
If you want a task to run overnight or on a strict schedule, wake the service with a free
external cron:

1. Sign up at [cron-job.org](https://cron-job.org) (free).
2. Create a cron job: **every 15 minutes**, URL
   `https://<your-service>.onrender.com/api/scheduled-tasks/tick`, method **POST**,
   with header `x-access-key: <your ACCESS_KEY>`.
3. Done. Each ping wakes the service if it slept and fires whatever is due; tasks
   whose time passed while asleep fire on the next ping.

Every fire still spends one run from the daily budget, and a fire that lands while the
agent is busy retries a few minutes later instead of being dropped. Set
`SCHEDULER_ENABLED=false` to turn the loop off entirely.

## One poller, always

The platform allows exactly **one** long-polling client per agent, and a second one kills the first
with a 409. So:

* Render polls when a WhatsApp token exists (this is the default — `POLLER_ENABLED` is unset).
* On your laptop, **do not set `WHATSAPP_TOKEN`**, or set `POLLER_ENABLED=false`, while Render owns
  the connection. If something is already polling and you try to verify the token elsewhere,
  `npm run verify` reports it as `conflict` — which means the token is fine.

## When something goes wrong

| Symptom | Look at |
|---|---|
| Build fails at `npm ci` | `render.yaml` already uses `npm ci --include=dev` — the `--include=dev` is required because the build needs esbuild, which is a devDependency |
| Boot exits with `DATABASE_URL is required` | The Neon string is missing or was pasted without `?sslmode=require` |
| Boot exits with `MASTER_KEY must be 64 hex characters` | Use exactly the output of `openssl rand -hex 32` — no quotes, no `0x` |
| Boot exits with `ACCESS_KEY must be at least 12 characters` | Only happens if you replaced the generated value with something short |
| Every mission fails `auth_failed` | The Gemini key is wrong or restricted — `npm run verify -- --key-only` |
| Missions fail `agent_unavailable` | The agent id was retired; update `ANTIGRAVITY_AGENT` (date-stamped) and redeploy |
| WhatsApp never answers | Settings → WhatsApp not connected → the reason is on the panel; `conflict` means another host is polling |
